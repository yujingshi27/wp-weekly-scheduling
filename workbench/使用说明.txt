WP 工作台 · 使用说明
====================

一个只在本机运行的网页工作台，包含「待办管理」和「工时筛选」两个模块。
数据保存在本机，不需要联网、不需要密码。

------------------------------------------------------------
一、怎么启动
------------------------------------------------------------
方法一（推荐先用）：双击  启动工作台.bat
    会出现一个黑色窗口，浏览器自动打开工作台页面。
    用完直接关闭这个黑窗口即可退出。

方法二：双击  WP工作台.exe
    效果一样，不用装 Python，发给别人也能用（自带运行环境）。
    注意：exe、data、config.json、backup、exports 要在同一个文件夹里。

打开后浏览器地址是：http://127.0.0.1:5000

------------------------------------------------------------
二、第一次使用：设置三个数据源（只需做一次）
------------------------------------------------------------
点顶部菜单「数据源设置」，按下面顺序做：

1. 填三个文件路径
   - Timesheet 文件（用于工时筛选）
   - WP服务单文件（用于取 Outlook Hours 预算）
   - 排班输出文件（用于取 DDL）
   每个框可以点「浏览」用弹窗选文件，也可以直接粘贴完整路径。
   填好后点「保存数据源」。

2. 设置 Timesheet 用哪几列
   点「读取表头」→ 页面会出现 7 个下拉框，已经帮你预填好推荐列：
     项目编号列 = Engagement Code
     员工列     = Employee Name
     manager 列 = COE Manager
     工时列     = Charge Hours
     期间列     = Transaction Cycle Date
     描述列     = Charge Description
     项目名称列 = Engagement Name
   如果没问题，直接点「保存列映射」。
   想改成“第几周”就把 期间列 改成 Fiscal Week。

3. 导入数据
   - 点「刷新 Timesheet」：第一次约 3 分钟（文件很大，48万行），
     之后筛选都是秒出结果。文件更新后再点一次即可。
   - 点「刷新预算」：几秒钟。

以上设置会记住，以后不用再设；换了文件用「浏览」重新选、再保存即可。

------------------------------------------------------------
三、待办管理（首页）
------------------------------------------------------------
- 顶部标签分区：今日得做 / 待完成 / 卡着 / 等反馈 / 归档，默认显示「今日得做」。
- 新建待办：点右上「+ 新建待办」，填任务名称、截止日期、状态、分类、四象限、标签、备注。
  新建时选的状态会直接生效（选“卡着”就进卡着区，不会再被丢进待完成）。
- 完成：点某条右边的「完成」，它会进归档区；
  如果是“常规重复”事项，会自动生成下一个周期的新待办。
- 状态：新建时可直接选，之后也能在每条右边的下拉框改成 待完成/今日得做/卡着/等反馈。
- 自动规则：新建、编辑、以及每次打开工作台时都会检查——
    截止日期 ≤ 今天且状态是 待完成/卡着/等反馈 → 立即变「今日得做」；
    已过期还没完成 → 保持「今日得做」并标红置顶。
- 分类：日常任务 / 临时任务（普通待办）、常规重复（按重复规则循环）、
     DDL（由排班输出的“项目关键节点”自动生成）。
- 四象限：未设置 / 重要且紧急 / 重要不紧急 / 紧急不重要 / 不紧急不重要。
     普通新建默认“未设置”；DDL 自动生成的默认“重要且紧急”；常规重复新一期沿用上一期。
- 排序：每个状态区里，先按截止日期从早到晚（没有截止日的排最后），
     同一天再按四象限（重要且紧急 → 重要不紧急 → 紧急不重要 → 不紧急不重要 → 未设置）。
- 归档区：可按任务名称搜索；进入归档满 7 天后自动彻底删除。
- 「刷新 DDL」按钮：重新读排班输出，更新 DDL 待办。
    DDL 日期改了会更新；已经完成的 DDL 不会被改动。

------------------------------------------------------------
四、工时筛选
------------------------------------------------------------
点顶部菜单「工时筛选」进入。

1. 先选「按项目」还是「按人」。
2. 输入条件：
   - 按项目：填项目 code（点「+ 添加项目」可加多个）；
             填 manager（点「+ 添加 manager」，支持模糊匹配，
             忽略大小写、包含即可，例如填 A 和 B = 名字里含 A 或含 B）。
   - 按人：只填 manager（同样支持多个、模糊匹配）。
3. 点「筛选」：网页先显示结果表，下面是「项目合计（合计工时 vs 预算）」，
   超预算的会标红。合计区按 code 升序。
4. 点「导出 Excel」：文件保存到 exports 文件夹（浏览器也会提示下载）。
   文件名示例：工时筛选_20261013_47129402等.xlsx
   （“按项目”用第一个 code，“按人”用第一个 manager，多个加“等”）
5. 结果为空会红字提示，重新输入即可，不会退出。
6. 「刷新 Timesheet」「刷新预算」两个按钮在页面右上，分别重新读文件。

------------------------------------------------------------
五、数据、配置、备份在哪里
------------------------------------------------------------
全部在 workbench 文件夹里：
  config.json  —— 你的设置（数据源路径、列映射）
  data\todo.db —— 待办的数据库
  backup\      —— 自动备份，每周一次，保留最近 7 份
  exports\     —— 导出的 Excel 文件

自动备份：每次打开工作台会检查“本周是否已备份”，
没备就自动复制一份 todo.db 到 backup 文件夹。

------------------------------------------------------------
六、常见问题
------------------------------------------------------------
问：双击 bat 后浏览器没打开？
答：等几秒；或手动在浏览器输入 http://127.0.0.1:5000

问：提示“文件不存在”？
答：去「数据源设置」重新指定该文件路径并保存。

问：提示找不到“项目关键节点”sheet？
答：说明排班输出文件不对，请在设置里换成正确的排班输出文件。

问：工时筛选结果为空？
答：检查 code / manager 是否写对；manager 是模糊匹配，写一部分也能命中。

问：刷新 Timesheet 很久没反应？
答：文件有 48 万行，第一次约 3 分钟属正常，请耐心等待不要关闭窗口。

问：想重新打包 exe？
答：双击 build_exe.bat（需要联网安装打包工具），完成后生成 WP工作台.exe。

问：不小心双击了两次，会不会开两个？
答：不会。工作台只允许开一个：第二次打开会自动连到已经开着的那个，不重复启动。

问：点「浏览」没反应或没弹框？
答：「浏览」会弹出 Windows 文件选择框（可能出现在窗口后面，注意任务栏）。
    如果没弹出，直接把完整路径粘贴到输入框也能用。

问：出现“请求失败 500”怎么办？
答：工作台会把详细错误写到 logs\error.log。可把该文件内容发给技术支持。
    常见原因是数据源文件正被 Excel 打开，先关掉 Excel 再刷新。

------------------------------------------------------------
七、目录结构（了解即可）
------------------------------------------------------------
workbench\
  启动工作台.bat        双击启动（开发方式）
  WP工作台.exe          打包后的独立程序
  build_exe.bat         重新打包 exe
  requirements.txt      依赖清单
  config.json           设置
  data\todo.db          数据库
  backup\               备份
  exports\              导出的 Excel
  logs\error.log        出错时的详细日志（排错用）
  app\                  程序本体（不用改动）
